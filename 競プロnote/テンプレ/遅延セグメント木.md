### コード

```python
from atcoder.lazysegtree import LazySegTree

# 例：区間加算・区間和
# S = (区間の合計, 区間の要素数)
def op(left, right):
    return (left[0] + right[0], left[1] + right[1])


# data に対して lazy を作用させる
def mapping(lazy, data):
    return (data[0] + lazy * data[1], data[1])


# 先に lazy_lower、後に lazy_upper を作用する合成写像
def composition(lazy_upper, lazy_lower):
    return lazy_upper + lazy_lower


e = (0, 0)  # op の単位元
id_ = 0     # mapping の恒等写像

a = [1, 2, 3, 4, 5]
seg = LazySegTree(
    op=op,
    e=e,
    mapping=mapping,
    composition=composition,
    id_=id_,
    v=[(x, 1) for x in a],
)

# [l, r) のすべての要素に x を加算
l, r, x = 1, 4, 10
seg.apply(l, r, x)

# [l, r) の和
print(seg.prod(l, r)[0])

# i 番目の値の取得・更新
i = 2
print(seg.get(i)[0])
seg.set(i, (100, 1))

# 全要素の和
print(seg.all_prod()[0])
```

### 解説

遅延セグメント木は、「区間に対する更新」と「区間に対する取得」をどちらも
$O(\log N)$ で行うデータ構造です。AtCoder Library の Python 版では
`atcoder.lazysegtree.LazySegTree` を使います。区間はすべて半開区間 `[l, r)` で指定します。

普通のセグメント木は各ノードに「その区間の和」や「その区間の最小値」を持ちます。
遅延セグメント木はそれに加えて、「このノードの子孫全体に、あとでこの更新を反映する」という予定も保持します。

例えば、長さ 8 の区間全体に `+3` するとき、8 個の葉を1つずつ更新する必要はありません。
その区間に対応するノードの情報だけを更新し、「子にはまだ `+3` を反映していない」と記録します。
後でその子の情報が必要になったときにだけ更新を伝播するのが「遅延評価」です。

AtCoder Library に渡すものは、大きく分けて次の2種類です。

- `S`：ノードが持つ「区間の情報」の型。`op` と `e` は `S` を扱います。
- `F`：遅延させる「区間への操作」の型。`mapping`、`composition`、`id_` は `F` を扱います。

Python では `S` や `F` という型を宣言しませんが、「今定義しているのは区間の情報か、操作か」を意識すると整理しやすくなります。

#### 何を設定するかの決め方

問題を見たら、次の順番で考えます。

1. **取得クエリから `S`、`op`、`e` を決める**
   - 区間和が欲しい → `op` は加算、`e` は `0`
   - 区間最小値が欲しい → `op` は `min`、`e` は `INF`
   - 区間最大値が欲しい → `op` は `max`、`e` は `-INF`
2. **更新クエリから `F` と `id_` を決める**
   - `+a` する更新 → `F` は加算値 `a`、何もしない値は `0`
   - `a` を代入する更新 → `F` は代入値 `a`、何もしない値は `None` など
   - `ax+b` に変換する更新 → `F` は `(a, b)`、何もしない値は `(1, 0)`
3. **1つのノード全体に更新した結果を考え、`mapping(f, x)` を決める**
4. **既に待っている操作 `g` の後に、新しい操作 `f` が来たと考え、`composition(f, g)` を決める**

`mapping` を考えたとき、ノードの現在の情報だけで更新後の情報を計算できなければ、`S` に情報を追加します。
区間加算・区間和で区間長を持たせるのがその代表例です。

#### 上のコードをどう導くか

「区間 `[l, r)` に `a` を加算」と「区間 `[l, r)` の和を取得」があるとします。

1. 欲しい値は区間和なので、左右のノードは加算で結合します。
2. しかし、長さ `length` の区間に `a` を加えると、区間和は `a * length` 増えます。合計だけでは更新後を計算できないため、`S = (sum, length)` とします。
3. すると左右の結合は `(sum1 + sum2, length1 + length2)`、その単位元は `(0, 0)` です。
4. 加算 `a` を区間情報に作用すると `(sum + a * length, length)` になります。これが `mapping` です。
5. 先に `+g`、後に `+f` するのは、まとめて `+(g+f)` するのと同じです。よって `composition(f, g) = f + g`、何もしない操作 `id_` は `0` です。

このように、`op` と `mapping` を別々に暗記するのではなく、「何を取得したいか」と「区間全体への更新でその情報がどう変わるか」から順に導きます。

#### 初期化に必要なもの

- `op(a, b)`：2つの区間の情報を結合する関数。上の例では合計と要素数をそれぞれ足します。
- `e`：`op` の単位元。どの値 `x` に対しても `op(e, x) == op(x, e) == x` となる値です。
- `mapping(f, x)`：遅延値 `f` をノードの値 `x` に作用させる関数です。
- `composition(f, g)`：遅延値を合成する関数。`g` を作用した後に `f` を作用する操作、つまり $f \circ g$ を返します。代入やアフィン変換のように順序が重要な操作では特に注意します。
- `id_`：何もしない遅延値。どの値 `x` に対しても `mapping(id_, x) == x` となる値です。
- `v`：元の配列。上の例では各要素 `x` を `(x, 1)` に変換して渡します。整数 `n` を渡すと、長さ `n` のすべての要素が `e` で初期化されます。

#### よくある組み合わせ

| 区間更新 | 区間取得 | `S` | `F` | `mapping(f, x)` | `composition(f, g)` | `e` | `id_` |
|---|---|---|---|---|---|---|---|
| 加算 `+a` | 最小値 | 最小値 `x` | 加算値 `f` | `x + f` | `f + g` | `INF` | `0` |
| 加算 `+a` | 最大値 | 最大値 `x` | 加算値 `f` | `x + f` | `f + g` | `-INF` | `0` |
| 加算 `+a` | 合計 | `(sum, size)` | 加算値 `f` | `(sum + f * size, size)` | `f + g` | `(0, 0)` | `0` |
| 代入 `=a` | 最小値 | `(minimum, size)` | 代入値 `f` | `(minimum, size)` if `f is None or size == 0` else `(f, size)` | `g if f is None else f` | `(INF, 0)` | `None` |
| 代入 `=a` | 合計 | `(sum, size)` | 代入値 `f` | `(sum, size)` if `f is None` else `(f * size, size)` | `g if f is None else f` | `(0, 0)` | `None` |
| 0/1 の反転 | 1 の個数 | `(ones, size)` | `True/False` | `(size - ones, size)` if `f` else `(ones, size)` | `f ^ g` | `(0, 0)` | `False` |
| `x -> ax+b` | 合計 | `(sum, size)` | `(a, b)` | `(a * sum + b * size, size)` | 下記 | `(0, 0)` | `(1, 0)` |

`S` が `(取得したい値, size)` のタプルなら、`op` は1要素目を和・最小値などの目的の演算で結合し、2要素目の `size` は加算します。
代入・区間最小値の例でも `size` を持つのは、要素のない区間 `e = (INF, 0)` に代入操作を作用させても `e` のままにするためです。

アフィン変換の合成は順序が重要です。既存の `g = (ag, bg)` を先に作用し、新しい `f = (af, bf)` を後に作用すると、

$$
f(g(x)) = af(agx + bg) + bf = (af \cdot ag)x + (af \cdot bg + bf)
$$

なので、`composition(f, g)` は `(af * ag, af * bg + bf)` です。問題に法 `MOD` があるときは、各計算の余りを取ります。

この表はそのまま暗記するより、上の4手順を自力で再現するための答え合わせとして使うのがおすすめです。

`composition` で迷ったら、適当な1要素 `x` を用意して実際に順番どおり操作します。
例えば代入で、先に `x = 3`、後に `x = 5` を行うと最後は `5` です。
つまり新しい代入操作 `f` が古い操作 `g` を上書きするので、`composition(f, g)` は `f` を返します。
`f` が「何もしない」を表す `None` のときだけ、古い操作 `g` を残します。

#### 設定が正しいかのチェック

特に `mapping` と `composition` に自信がないときは、小さな値で次を確認します。

- `op(e, x) == op(x, e) == x`
- `mapping(id_, x) == x`
- `composition(id_, f) == composition(f, id_) == f`
- `mapping(f, mapping(g, x)) == mapping(composition(f, g), x)`
- `mapping(f, op(x, y)) == op(mapping(f, x), mapping(f, y))`

最後の式は、「左右を先に結合してから更新」と「左右を更新してから結合」の結果が同じという条件です。
これが成り立たないと、ノード全体にまとめて操作することができません。

例えば、「区間の各値を `min(x, a)` にする」と「区間和」の組み合わせは、合計と長さだけから更新後の合計を決められません。
そのため、上の簡単な `LazySegTree` の設定では扱えず、Segment Tree Beats など別の工夫が必要です。

#### 主なメソッド

| メソッド | 内容 | 計算量 |
|---|---|---|
| `seg.set(p, x)` | `p` 番目を `x` に更新 | $O(\log N)$ |
| `seg.get(p)` | `p` 番目を取得 | $O(\log N)$ |
| `seg.prod(l, r)` | `[l, r)` を `op` でまとめた値を取得 | $O(\log N)$ |
| `seg.all_prod()` | 全区間を `op` でまとめた値を取得 | $O(1)$ |
| `seg.apply(p, f=f)` | `p` 番目に `f` を作用 | $O(\log N)$ |
| `seg.apply(l, r, f)` | `[l, r)` のすべての要素に `f` を作用 | $O(\log N)$ |
| `seg.max_right(l, g)` | `g(prod(l, r))` が真となる右端 `r` を二分探索 | $O(\log N)$ |
| `seg.min_left(r, g)` | `g(prod(l, r))` が真となる左端 `l` を二分探索 | $O(\log N)$ |

`max_right` と `min_left` で使う判定関数 `g` は、`g(e) == True` を満たし、判定結果が区間の拡大に対して単調に変化する必要があります。

#### 注意点

- AtCoder の問題文が 1-indexed の閉区間 `[L, R]` であれば、通常は `L -= 1` として `[L, R)` のまま `apply` や `prod` に渡します。
- Python 版で1点だけに操作する場合は、引数の対応を明確にするため `seg.apply(p, f=f)` と `f` をキーワード引数で渡します。区間操作は `seg.apply(l, r, f)` です。
- `mapping` は、「ノードが表す区間全体に操作した後の情報」を返す必要があります。区間和に一律加算する場合は区間長が必要なため、値と一緒に要素数を持たせます。
- `e` と `id_` は異なる役割です。`e` はデータを結合するときの単位元、`id_` は遅延操作の単位元です。
