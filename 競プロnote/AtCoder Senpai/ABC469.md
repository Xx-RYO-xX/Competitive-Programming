## B - Isolated Seats

- [Xx_RYO_xXの提出](https://atcoder.jp/contests/abc469/submissions/78003150)
    

### あなたの方針

各椅子について、

1. 自分が空席 `x`
    
2. 左端、または左も空席
    
3. 右端、または右も空席
    

をそのまま確認しています。

```python
for i in range(n):
    if s[i] == "x":
        if i - 1 == -1 or s[i - 1] == "x":
            if i + 1 == n or s[i + 1] == "x":
                ans += 1
```

計算量は `O(N)` で、方針は正しいです。

### 上位提出との比較

kotatsugameは、同じ条件を早期`continue`で書いています。

```cpp
for(int i=0;i<N;i++) if(S[i]=='x')
{
    if(i>0&&S[i-1]=='o') continue;
    if(i+1<N&&S[i+1]=='o') continue;
    ans++;
}
```

Nachiaも、判定変数を使って同じ条件を列挙しています。

```cpp
bool ok = 1;
if(S[i] == 'o') ok = 0;
if(i != 0 && S[i-1] == 'o') ok = 0;
if(i != N-1 && S[i+1] == 'o') ok = 0;
ans += ok;
```

PCTprobabilityは両端に番兵を置き、`xxx`の個数として数えています。

```cpp
s += 'x';
reverse(s.begin(), s.end());
s += 'x';

for(int i=0; i+2<s.size(); i++)
    if(s.substr(i,3) == "xxx") a++;
```

本質的にはすべて同じです。

### 実装上の改善点

次の入力処理は、末尾に改行があることを仮定しています。

```python
s = list(input())[:-1]
```

AtCoderの通常入力では問題になりませんが、最終行に改行がない入力では、本来の最後の文字を削除してしまいます。

```python
s = input().strip()
```

または、

```python
s = input().rstrip()
```

とする方が安全です。

文字列を`list`に変換する必要もありません。Pythonの文字列は添字アクセスできるので、次のように書けます。

```python
s = input().strip()

ans = 0
for i in range(n):
    if s[i] == "o":
        continue
    if i > 0 and s[i - 1] == "o":
        continue
    if i + 1 < n and s[i + 1] == "o":
        continue
    ans += 1
```

### 評価

アルゴリズム上の問題はありません。上位陣と同じ`O(N)`解法です。

改善対象は、`[:-1]`による改行除去と、条件分岐の読みやすさだけです。

## C - Cantrip

- [Xx_RYO_xXの提出](https://atcoder.jp/contests/abc469/submissions/78017695)
    

### あなたの方針

`x`が出現する位置を列挙し、初期袋数`k`に対して、

- `k`個目の`x`が存在するなら、その位置
    
- 存在しなければ`N`
    

を答えています。

```python
xx = []
for i in range(n):
    if s[i] == "x":
        xx.append(i + 1)

for k in range(1, n + 1):
    if k <= len(xx):
        ans.append(str(xx[k - 1]))
    else:
        ans.append(str(n))
```

これは正しい`O(N)`解法です。

### なぜ「k個目のxの位置」になるのか

食べた袋の個数を`L`、その中にある`o`の個数を`H`とします。

最初に`k`個を食べ、その後は持っている`o`を1個消費するたびに1個追加で食べるので、列の途中で停止したなら、

```text
L = k + H
```

です。

一方、食べた`x`の個数を`X`とすると、

```text
L = H + X
```

なので、

```text
X = k
```

となります。

つまり、列の途中で止まるのは、ちょうど`k`個目の`x`を食べた地点です。`x`が`k`個未満なら、最後まで食べられます。

この不変量を正しく見抜けています。

### 上位提出との比較

Nachiaのコードは、ほぼ同じ内容です。

```cpp
V<ll> ans(N, N);
ll p = 0;

REP(i,N) if(S[i] == 'x'){
    ans[p++] = i + 1;
}
```

kotatsugameも同じです。

```cpp
vector<int> BAD;

for(int i=0;i<N;i++)
    if(S[i]=='x') BAD.push_back(i);

for(int k=1;k<=N;k++)
{
    if(BAD.size()<k) cout<<N<<"\n";
    else cout<<BAD[k-1]+1<<"\n";
}
```

したがって、**方針レベルでは上位提出と完全に一致しています。**

### 改善点1: メモリ使用量

この提出のメモリ使用量は **326,016 KiB** で、今回の提出の中でも突出しています。

主な要因は、次の3つを同時に保持していることです。

```python
s = list(input())[:-1]  # N個の参照を持つlist
xx = []                 # 最大N個のPython整数
ans = []                # N個の文字列
```

特に、`ans`にN個の文字列を保存する構造はPyPyで大きなメモリを消費します。

`x`の位置はそのまま答えの先頭部分なので、出力バッファへ直接書けます。

```python
import io
import sys

def main():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    out = io.StringIO()
    x_count = 0

    for i, c in enumerate(s, 1):
        if c == "x":
            out.write(str(i))
            out.write("\n")
            x_count += 1

    out.write((str(n) + "\n") * (n - x_count))
    sys.stdout.write(out.getvalue())

if __name__ == "__main__":
    main()
```

これなら、`s`と最終出力文字列程度しか保持しません。

### 改善点2: 方針発見までの時間

上位先行組は03:03〜07:47でACしていますが、あなたは19:15でした。

最終コードが短く正しいことから、実装よりも、

> 操作をそのままシミュレーションせず、食べた`o`と`x`の個数の関係式に変換する

部分で時間を使った可能性があります。

今回のコードから得るべき復習ポイントは、解法そのものではなく、

```text
食べた総数 = 初期個数 + 消費したoの個数
```

という保存則を、より早く式にすることです。

### 評価

- 方針: 上位提出と同一で非常に良い
    
- 計算量: 最適
    
- 改善対象: 方針の言語化速度とPythonでの出力メモリ

## D - The Big Two

- [Xx_RYO_xXの提出](https://atcoder.jp/contests/abc469/submissions/78053063)
    

この問題が今回の最大の改善対象です。

### 問題のグラフとしての見方

各トーナメントの決勝進出者 `(A_i,B_i)` を無向辺と考えます。

求める `(x,y)` は、

> すべての辺について、端点の少なくとも一方が`x`または`y`

となる頂点対です。

つまり、**大きさ2の頂点被覆を数える問題**です。

---

### あなたの方針

各頂点の出現回数を数え、

```python
if cnt[i] >= n / 2:
    kouho.append(i)
```

を満たす頂点だけを`x`の候補にしています。

`x`を固定した後は、`x`が含まれない辺の共通部分を取り、もう一方の頂点`y`を求めています。

```python
y = {0}

for i in range(m):
    if i not in zoku[x]:
        if y == {0}:
            y = ab[i]
        else:
            y &= ab[i]

        if len(y) == 0:
            break
```

後半の「`x`を含まない全辺の共通端点が`y`」という考え方自体は正しいです。

問題は、`x`の候補の選び方と、対象となる辺が0本の場合です。

---

### WA原因1: `cnt[i] >= n / 2`に根拠がない

```python
if cnt[i] >= n / 2:
```

では、プレイヤー数`N`を閾値に使っています。しかし条件の数はトーナメント数`M`です。

さらに、この問題では次数による候補選択自体が不要です。

例えば次の入力を考えます。

```text
3 1
1 2
```

辺は`(1,2)`の1本だけです。

有効な組は、

```text
(1,2)
(1,3)
(2,3)
```

の3組です。

ところが、

```text
n / 2 = 1.5
cnt[1] = cnt[2] = 1
```

なので、あなたのコードでは`kouho`が空になり、`0`を出力します。

### 正しい候補削減

最初の辺を `(A_0,B_0)` とします。

有効な組`(x,y)`は最初の辺もカバーしなければならないので、必ず、

```text
xまたはyがA_0
```

あるいは、

```text
xまたはyがB_0
```

を満たします。

したがって、片方の頂点として調べる必要があるのは、最初の辺の2頂点だけです。

Nachiaはこの性質をそのまま利用しています。

```cpp
REP(t,2){
    ll a = A[0];

    ll p = 0;
    while(p < M && (A[p] == a || B[p] == a)) p++;

    // ...
    swap(A, B);
}
```

StarSilkも、最初の辺の`a[0]`と`b[0]`だけを調べています。

```cpp
// x = a[0] を調査
for(i=1;i<m;i++)
{
    if(a[i]==a[0]||b[i]==a[0]) continue;
    cnt[a[i]]++;
    cnt[b[i]]++;
}

// x = b[0] を調査
```

これはヒューリスティックではなく、最初の辺を使った完全な候補削減です。

---

### WA原因2: すべての辺が`x`を含む場合

初期値として、

```python
y = {0}
```

を使用しています。

しかし、すべての辺が`x`を含む場合、`y`は更新されず、最後に、

```python
ans.add(tuple(sorted((x, 0))))
```

が実行されます。

本来この場合、`y`は`x`以外のすべての頂点から選べます。

例えば、

```text
4 2
1 2
1 3
```

では、`x=1`とすればすべての辺がカバーされるので、

```text
(1,2)
(1,3)
(1,4)
```

がすべて有効です。

しかし、あなたのコードでは`(0,1)`という番兵との組を1個だけ数えてしまいます。

---

### 上位提出も同じ端ケースでWAしている

PCTprobabilityの最初のD提出も、対象となる辺が0本の場合を取りこぼしています。

最初のWAコードでは、

```cpp
map<ll,ll> d;
ll cnt = 0;

// xを含まない辺についてdを更新

for(auto e:d){
    if(e.se == cnt){
        // 答えに追加
    }
}
```

としていました。

`cnt == 0`の場合は`d`が空なので、「すべての頂点が候補」というケースを列挙できません。

最終ACでは、

```cpp
vector<ll> d(n);

for(int j=0;j<n;j++){
    if(j!=c[i] && d[j]==cnt){
        s.insert({c[i],j});
        s.insert({j,c[i]});
    }
}
```

と、0回出現する頂点も含めて全頂点を走査するように修正しています。

- [PCTprobabilityの1回目のD WA](https://atcoder.jp/contests/abc469/submissions/78012270)
    
- [PCTprobabilityの2回目のD WA](https://atcoder.jp/contests/abc469/submissions/78018582)
    
- [PCTprobabilityの最終AC](https://atcoder.jp/contests/abc469/submissions/78021030)
    

この問題は上位者も端ケースで複数回WAしています。ただしPCTprobabilityは25:22でACしており、修正時間を確保できました。

あなたは99:51で初提出だったため、同じ種類のバグを発見する時間がありませんでした。

---

### 改善点3: データ構造が重い

次の構造を作っています。

```python
zoku = [set() for _ in range(n + 1)]
ab.append(set((a, b)))
```

- 各頂点について、含まれる辺番号の`set`
    
- 各辺について、2要素の`set`
    

を持つため、メモリ使用量が **223,780 KiB** まで増えています。

この問題では、辺を普通のタプルとして保存し、最大数回走査するだけで十分です。

---

### 修正版

あなたの「残った辺の共通端点を探す」という発想を、最初の辺による候補削減と組み合わせると、次のように書けます。

```python
def main():
    import sys

    input = sys.stdin.readline

    n, m = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(m)]

    ans = set()

    def check_first_vertex(x):
        first_uncovered = None

        for a, b in edges:
            if a != x and b != x:
                first_uncovered = (a, b)
                break

        # すべての辺がxを含む
        if first_uncovered is None:
            for y in range(1, n + 1):
                if y != x:
                    ans.add((min(x, y), max(x, y)))
            return

        # yは、最初に見つけた未被覆辺のどちらかでなければならない
        for y in first_uncovered:
            if y == x:
                continue

            ok = True
            for a, b in edges:
                if x != a and x != b and y != a and y != b:
                    ok = False
                    break

            if ok:
                ans.add((min(x, y), max(x, y)))

    a0, b0 = edges[0]
    check_first_vertex(a0)
    check_first_vertex(b0)

    print(len(ans))


if __name__ == "__main__":
    main()
```

### 計算量

最初の辺の2頂点について、それぞれ最大数回辺を走査するだけなので、

```text
O(N + M)
```

です。

### D問題での学習ポイント

今回の候補削減は、

```text
次数が多そうな頂点を調べる
```

ではなく、

```text
すべての解は、最初の制約を満たさなければならない
```

という論理から行うべきでした。

この差が、今回のWAの本質です。

## F - GCD Maximum Spanning Tree

- [Xx_RYO_xXの提出](https://atcoder.jp/contests/abc469/submissions/78038634)
    

今回最も高く評価できる提出です。

### あなたの方針

重み`g`を大きい順に処理し、`g`の倍数である要素をUnion-Findで接続しています。

```python
for gg in range(1, amax + 1)[::-1]:
    u = -1

    for x in range(gg, amax + 1, gg)[::-1]:
        if x in sonzai:
            if u == -1:
                u = bisect_left(a, x)
            else:
                v = bisect_left(a, x)

                if not uf.same(u, v):
                    uf.union(u, v)
                    ans += gg
```

これは最大全域木に対するクラスカル法です。

### 正当性

`g`の倍数である2つの値の最大公約数は、少なくとも`g`です。

したがって、`g`を大きい順に処理すると、

- より大きいGCDで接続できる頂点は既に接続済み
    
- まだ別成分なら、重み`g`の辺として接続可能
    

となります。

`g`の倍数全体は実質的にクリークですが、全辺を作る必要はありません。各連結成分を星形に接続すれば十分です。

あなたのコードは、最初に見つけた頂点`u`を中心にして接続しています。

---

### 上位提出との比較

kotatsugameも、値から頂点番号への配列を用意し、同じ処理をしています。

```cpp
for(int g=1000000;g>=1;g--)
{
    int p=0;

    for(int i=g;i<=1000000;i+=g) if(ID[i]>0)
    {
        if(p>0&&!uf.same(p,ID[i]))
        {
            uf.merge(p,ID[i]);
            ans+=g;
        }
        p=ID[i];
    }
}
```

StarSilkも同じです。

```cpp
for(i=1000000;i>0;i--)
{
    lst=-1;

    for(j=i;j<=1000000;j+=i)
    {
        if(vis[j])
        {
            if(lst==-1) lst=j;
            else ans += i * merge(lst,j);
        }
    }
}
```

SakuraCatは、各`g`について異なるDSU根だけを列挙し、

```cpp
ans += i * (t - 1ll);
```

としてまとめて接続しています。

Nachiaも実装形式は違いますが、「`g`の倍数に属する成分を重み`g`で統合する」という本質は同じです。

- [NachiaのF提出](https://atcoder.jp/contests/abc469/submissions/78016140)
    
- [kotatsugameのF提出](https://atcoder.jp/contests/abc469/submissions/78021408)
    
- [StarSilkのF提出](https://atcoder.jp/contests/abc469/submissions/78030922)
    

### 評価

**方針レベルでは上位提出と一致しています。**

500点問題でこの変形クラスカル法を組み立て、Pythonで1.6秒で通している点は明確な強みです。

---

### 実装上の差1: `set`と`bisect_left`

あなたのコードは、値の存在確認と添字取得を別々に行っています。

```python
sonzai = set(a)

if x in sonzai:
    v = bisect_left(a, x)
```

`A`が狭義単調増加であるため正しく動きますが、存在する値を見つけるたびに二分探索を行います。

上位提出は、

```cpp
ID[a] = i;
```

という直接参照配列を使っています。

Pythonでも、次のように値から頂点番号を直接引けます。

```python
index = [-1] * (amax + 1)

for i, x in enumerate(a):
    index[x] = i
```

これにより、

```python
v = index[x]
if v == -1:
    continue
```

だけで済みます。

---

### 実装上の差2: `same`の後に再び`find`している

現在は、

```python
if not uf.same(u, v):
    uf.union(u, v)
    ans += gg
```

となっています。

`same`で2回`find`し、その後`union`でも2回`find`しているため、成功するマージでは探索を重複して行います。

上位提出のStarSilkは、`merge`自身が成功・失敗を返しています。

```cpp
int merge(int x,int y){
    x=findfa(x);
    y=findfa(y);

    if(x==y) return 0;

    fa[x]=y;
    return 1;
}

ans += i * merge(lst,j);
```

PythonのUnion-Findも、次の形にすると簡潔です。

```python
def union(self, x, y):
    x = self.find(x)
    y = self.find(y)

    if x == y:
        return False

    if self.parents[x] > self.parents[y]:
        x, y = y, x

    self.parents[x] += self.parents[y]
    self.parents[y] = x
    return True
```

呼び出し側は、

```python
if uf.union(u, v):
    ans += g
```

だけになります。

### 改善版

```python
class UnionFind:
    def __init__(self, n):
        self.parent = [-1] * n

    def find(self, x):
        while self.parent[x] >= 0:
            if self.parent[self.parent[x]] >= 0:
                self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, x, y):
        x = self.find(x)
        y = self.find(y)

        if x == y:
            return False

        if self.parent[x] > self.parent[y]:
            x, y = y, x

        self.parent[x] += self.parent[y]
        self.parent[y] = x
        return True


def main():
    import sys

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    max_a = a[-1]
    index = [-1] * (max_a + 1)

    for i, x in enumerate(a):
        index[x] = i

    uf = UnionFind(n)
    ans = 0

    for g in range(max_a, 0, -1):
        representative = -1

        for multiple in range(g, max_a + 1, g):
            v = index[multiple]

            if v == -1:
                continue

            if representative == -1:
                representative = v
            elif uf.union(representative, v):
                ans += g

    print(ans)


if __name__ == "__main__":
    main()
```
